# Source-scoped historical reasoning (experimental v1)

This opt-in mode is separate from saved `staged` and `staged-compact`
contracts. No older retrospective output is rewritten. It reduces the
chance that one long constrained JSON string clips the final explanation.

## Pipeline

1. Generate and validate cutoff-visible source-anchored change facts using
   the existing evidence-first model draft.
2. Generate one short model explanation and limitation for **every claim**
   in each newly visible official source, using one narrowly scoped structured
   model call **per claim**. Provenance IDs come from the scoped official
   input, not model-generated ID echoes. Preserve model-authored prose
   verbatim. Each explanation ends in punctuation and passes the
   no-market-outcome check. Any failure stops the run; never substitute
   curator text for model-authored output.
3. Assemble the source prose verbatim in dated source order, without a
   separate long free-form narrative generation call. Retain all individual
   claims and diagnostics for human review.
4. For **each question**, screen **every cutoff-visible official claim**
   into DIRECT_ANSWER, INTERMEDIATE_DECISION, RELATED_CONTEXT or
   NOT_RELEVANT. Preserve the full screening ledger including negative
   selections and provider diagnostics, then generate a separate answer from
   the screened evidence. Earlier question outcomes and editorial future
   transitions are never included. Provenance references are attached from
   screened official claims rather than generated by the answer model.
   The legacy model question status remains unchanged.
5. Separately diagnose token-limit termination, invalid JSON, suspected
   JSON Schema string boundary, a normal provider stop, and unavailable
   metadata. Normal stop **never** proves semantic completion.

The two question axes have different meanings:

- `regulatoryActionProgress`: NOT_OBSERVED, ANNOUNCED, AUTHORIZED,
  IMPLEMENTING, COMPLETED, UNKNOWN. The status concerns what the
  regulator actually announced or what implementation is evidenced.
- `requestedEvidenceStatus`: NOT_OBSERVED, PARTIAL, DIRECTLY_OBSERVED.
  This describes whether the *exact documents or answer requested*
  are visible, not how far the regulatory process has progressed.

For FAA 2024-01-24, authorization of the 737-9 MAX inspection/maintenance
process is not proof of completion of inspections on each plane. Increased
Boeing production oversight is not a finished audit. Separate 737-900ER
visual-inspection recommendations must not become a 737-9 MAX approval.
The same distinction applies to FDA authorization/approval versus missing
underlying manufacturer filings or internal review records.

## Real-model evaluation

On a Mac with existing Ollama `gemma4:e2b` installed, run this **once**
with a new output path; do not overwrite earlier staged-compact evidence:

```bash
DATA="$HOME/Library/Application Support/TrisMarketEventIntelligence"
bash scripts/news-learning-review.sh historical-event-chain \
  --chain research/faa-7379max-january-2024-event-chain.json \
  --question-tracks research/faa-2024-question-lifecycle.json \
  --sequence 2024-01-13 2024-01-25 \
  --reasoning-mode staged-composed \
  --run --model gemma4:e2b \
  --output "$DATA/faa-evidence-composed-v1.json"
```

Then compare the two preserved runs without asserting equivalence of model
effort, since composed mode makes **1 + N new source claims + 2 × Q visible research questions**
calls per cutoff, versus 2 in staged-compact. Compare source coverage,
complete prose, contradicting agency/product scope, missing documents,
reported token consumption and false status changes. Generated prose and
question axes are structurally reviewed, **not** semantically verified.
Date-only release chronology does not establish historical publication-time
snapshots, point-in-time verification, economic effects or causality.

Both the cutoff-visible official evidence and model-generated text must be
reviewed by a human before treating explanations as factual.

## Real FAA 2024-01-13/25 feedback (first prospective v1 run)

The first real composed run used eight Gemma4 calls and successfully avoided
visible clipped prose. However, on January 25 it cited the January 12 pending
procedure announcement for a still-UNKNOWN approval despite a January 24
procedure-approval source being visible. It also omitted the January 24 MAX
production-expansion prohibition because the single-source explanation chose
only one of the release's two distinct claims. These are substantive failures,
not evidence that success is guaranteed merely because JSON parses.

The follow-up revision requires all official claims to be narrated and
includes validated phase-one model assessments in the independent question
analysis. Run a **new output file name** for the next prospective comparison:
`faa-evidence-composed-v2.json`. Keep v1 untouched. This is still not
verified semantic correctness or historical PIT.

## FAA v3 failure and response

The real FAA v3 run failed before producing its output with
`COMPOSED_SOURCE_CLAIM_COVERAGE_INVALID`. The old exception did not
identify which of the multiple required model-authored claim IDs or prose
fields failed, so no narrower cause is proven by that log. The revised
mode makes one model call per claim, attaches prevalidated cutoff-visible
IDs outside the model text, and rejects incomplete explanation/limitation
sentences with a source-claim-specific error. More inference calls are an
explicit tradeoff for a smaller output contract. Old v1/v2 are preserved.
The next prospective test should use `faa-evidence-composed-v4.json`.

## Cross-event evidence selection feedback (FAA v4 / FDA v1)

Both real Gemma4 runs finished 12 calls each and generated complete short
prose for all eight official claims. The FAA January 25 oversight question
nevertheless omitted the later no-production-expansion action from its
supporting references, even though it narrated that action elsewhere.
The FDA October 4 question about original manufacturer filing receipts and
FDA internal review records likewise cited only June's anticipated filings,
ignoring the later mRNA product authorization as an intermediate decision.
The later authorization does not establish underlying internal records.
Both defects support a shared *question-to-evidence selection* weakness;
this diagnosis is not independent verification of all generated history.

The subsequent evidence-screening design separates **relevance recall**
from **status inference**. Each question's cutoff-visible source claims
receive a model-authored role (including NOT_RELEVANT). The synthesis
operates only on selected claims and cannot introduce its own provenance
IDs. The full relevance decisions remain visible to human reviewers, so
incorrect omissions are inspectable rather than silently treated as truth.
A product authorization is not operational completion; a production
restriction is an intermediate official decision, not completed audit
findings. No FAA/FDA-specific code-based override auto-corrects model
interpretations. Expect 18 model calls for each two-cutoff benchmark with
two questions per cutoff and four new claims per cutoff. The next real
cross-event outputs should be **new** `faa-evidence-composed-v5.json` and
`fda-evidence-composed-v2.json`, preserving all old artifacts.

## FAA v5 question answer failure: output contract simplification

Real Gemma4 FAA v5 execution repeatedly rejected a freeform final answer for
`faa-2024-boeing-production-oversight-outcome` because
`EXPLANATION_INCOMPLETE` persisted after the one permitted retry. The
question evidence screening had run, but no complete saved output exists;
this **does not verify** whether the screening recalled the January 24
decision. The correction keeps per-question evidence screening and model
classification of the two regulatory/evidence-state enums, but no longer
asks that final call to generate prose. Its explanation is a bounded,
**verbatim** concatenation of the cutoff-visible, precurated official claim
texts selected by the relevance screen (highest-priority selected claim
first), with an explicitly templated generic limitation based on the
model-classified evidence status. The status classification remains
model-authored and unverified. A source claim may be omitted from the
short narrative due to the 450-character field limit; the full selected
`supportingEvidence` and the full screen ledger are retained separately.
This replaces persistent text-level truncation failure without silently
editing a model sentence or inventing source references. The original
curated claim snippets are not authenticated historical page snapshots.
The next prospective outputs should use new filenames
`faa-evidence-composed-v6.json` and `fda-evidence-composed-v3.json`.
