# Stage 6: Gemma original article outcome validation

This research command joins **existing** `gemma_original_article_review_v2` JSON artifacts to **sourced historical adjusted-close data**. It neither rewrites the production SQLite database nor triggers Ollama, collectors, timers or trading.

## Required input

- `--gemma-dir`: existing `main-validation-gemma` results generated by `gemma_original_article_batch_cli`. Only successful article JSON files belong here. The file-level SHA-256 of every prediction is preserved in the output.
- `--mappings`: CSV with columns `target,market,symbol,benchmark,verified_at`. Targets must exactly match the Gemma-generated target string; `market` is XKRX, XNAS or XNYS; `verified_at` must be a timezone-aware date when the mapping is demonstrably supported by records available at that time. Do **not** backdate mappings to make a historical evaluation succeed.
- `--prices`: CSV with `symbol,date,adjusted_close,source`, one row per symbol and trading date. `source` must identify the actual data provider / export. Populate with genuine, authorized historical observations, not generated or placeholder prices. Include both subject and benchmark adjusted closes for the entry date and future dates.
- `--price-source`: human-readable dataset identification and coverage/version.
- `--output`: new JSON filename. Existing output is never overwritten.

Example:

```bash
DATA="$HOME/Library/Application Support/TrisMarketEventIntelligence"
python -m tris_market_event_intelligence.market_outcome_validation_cli \
  --gemma-dir "$DATA/main-validation-gemma" \
  --mappings "$DATA/stage6-verified-target-map.csv" \
  --prices "$DATA/stage6-actual-adjusted-daily.csv" \
  --price-source "provider/export/version and capture date" \
  --output "$DATA/stage6-outcomes-v1.json"
```

This is a **daily-bar validation bridge**: 1- and 5-trading-session returns, benchmark-relative returns, per-impact CORRECT/INCORRECT/ABSTAINED/UNAVAILABLE status and coverage counts. A daily entry is the first available session close on a date strictly after the article's **exchange-local** publication date. Missing days are not filled. Outcomes may miss immediate intraday reactions. For 1-hour and minute reactions, use the separate intraday research pipeline after source-specific coverage and an authenticated session calendar are provided.

The direction deadband is ±0.1% of *absolute adjusted return*; benchmark-relative returns are reported separately and are not retroactively chosen as the scoring basis. This rule must be fixed before looking at evaluation labels.

## Important epistemic limits

The existing article batch explicitly sets `predictionSealedBeforeOutcome=false`. These outputs remain **RETROSPECTIVE_UNSEALED**, regardless of whether subsequent label directions happen to match. Hashing them today proves integrity from today forward, not that a historical prediction existed at publication time. They must never be represented as prospective historical forecasting accuracy or a causal effect of news.

Target mappings with `verified_at` later than the publication date are excluded as `MAPPING_NOT_POINT_IN_TIME`. Unmapped targets are separately reported. The daily study is descriptive and does not remove market confounders beyond the simple benchmark comparison. A stronger validation requires a point-in-time historical replay, proper external test period, independent source availability audit, and comparison against naive market baselines.

This module does **not** provide a new market-data subscription or downloader. Price observations must first be obtained from a licensed/reliable provider and exported in the required format. There are **no measured accuracy results** until that real dataset is supplied and the command is actually executed.
